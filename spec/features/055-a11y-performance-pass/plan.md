# Plan — Accessibility and performance pass

> Feature: `055-a11y-performance-pass` · Based on: [spec.md](./spec.md) · Created: 2026-11-19

## Technical approach

Two halves, in the mission's order. Every change is measured against a
recorded "before".

### Part A — Accessibility (A1–A6)

1. **Contrast, one rule (D2).** Tailwind v4's `tailwind.config.ts` is ignored
   (roadmap bug), so the rule lives in the classes themselves:
   - **dark sections** (`#0a0a0a`, `#111`, `#161616`): secondary text is
     `text-gray-400` (≥ 6.5:1 on all three), never `text-gray-500`/`600`;
   - **light grey surfaces** (`bg-gray-100`): secondary text `text-gray-600`
     (≥ 7:1), never `text-gray-500`.
   Applied in every dark page container (`LocationDetail`, `ServiceDetail`,
   `AboutUs`, `/services`, `/locations`, `/guides`, `/contact`,
   `/legal-policies`, the shared breadcrumb on dark heroes) and the size page's
   grey pills. **Guard:** `darkContrast.guard.test.ts` lists those files and
   fails on `text-gray-500`/`text-gray-600` in them; `npm run a11y` catches the
   rest on rendered pages.
2. **Targets (D3).**
   - `LocationsSlider` dots: the visible 8 px pill stays inside a 24 × 24 px
     `<button>` (padding, transparent), so the look is unchanged.
   - `TireCard` size pill: a 24 px tall link (vertical padding / `min-h-6`)
     with the pill drawn inside — same look, larger target.
   - `InfoSlider` dots get the same treatment if present on audited pages.
3. **Label in name (A4).** `LocationCard`'s address control is navigation, so
   it becomes a real `<a href={mapLink} target="_blank" rel="noopener
   noreferrer">` instead of a `<button>` with `window.open`: its name is its
   visible text (address and area) plus a screen-reader "(opens Google Maps in
   a new tab)", and it gains copy-link and middle-click. The 023 spacing rule.
4. **Structure (A5).**
   - `ArrowsToRight` icon: the `clipPath` id comes from `useId()` (or the clip
     is removed if it clips nothing) — no duplicate ids when the icon renders
     twice.
   - Size and brand pages: a section `<h2>` above the card grid ("Tires in
     235/45/18", "Michelin tires in stock") so cards' `<h3>` follow an `<h2>`.
5. **Logos (A6, D4).**
   - Approval sheet first: for the 24 brands, the official logo URL and a
     preview on one page for the owner. **Each download is asked for before it
     happens.** Approved files are converted to `{brandId}-logo.webp` at the
     existing size and added to `public/assets/images/TireBrand/`.
   - `brandLogos.ts`: the set of brand ids that have a file, **generated by a
     script** from the folder and checked by a test (folder ↔ list), so
     `BrandImage` renders the name as styled text — without requesting a
     missing file — for any brand not in the set. No more 404s.
6. **`npm run a11y` (D6).** `scripts/a11y-check.mjs`: builds nothing itself;
   starts `next start` on a free port over the existing build, runs Lighthouse
   (accessibility only) on the key pages (home, `/tires`, `/tires/used`, a
   tire page, a store page, a service page, `/about-us`, a size page, a brand
   page, `/checkout`), mobile and desktop, and fails on `color-contrast`,
   `target-size`, `label-content-name-mismatch`, `duplicate-id*`,
   `heading-order`, or any score < 100 not on an allow-list. Every allow-list
   entry names the audit and page it exempts and a written reason, and the
   script prints them on every run.
   Lighthouse pinned as a **devDependency** (`lighthouse@13.6.0`) instead of
   `npx` downloads on every run. Added to the Definition of Done in
   `tech-stack.md`, **after `npm run build`** (it runs over the build) and, like
   `perf:budget`, as a local pre-deploy gate, not a CI step.

### Part B — Performance (P1–P4, D5)

1. **Baseline** (`scripts/perf-lab.mjs`, reusing the 052 review's runner):
   production build, 5 Lighthouse runs per page and form factor (for the
   baseline and the final measure only; checks between changes use 3 runs on
   the affected page — a full 5-run pass is ~30–40 min), medians of
   LCP, TBT, CLS, FCP, TTFB, plus the LCP element and long tasks, written to
   `spec/features/055-…/baseline.json` and summarised in `results.md` —
   **before any Part B change**.
2. **Known causes to fix, each measured after:**
   - **Every brand logo is `priority`** (`BrandImage`): 20–24 high-priority
     preloads per listing compete with the real LCP image. Only the first
     card's logo (or none) is eager; the rest lazy.
   - **LCP discovery:** for each page, the baseline names the LCP element; the
     LCP image gets `priority`/`fetchPriority="high"` and nothing else above
     the fold does (`optimize-image-priority` guide).
   - **Home TBT:** the baseline's long tasks name the scripts; likely suspects
     are client components that hydrate at once (hero, search, sliders, 3D
     preview, AI chat). Defer what is below the fold or not needed until
     interaction (`next/dynamic`, `content-visibility`, idle hydration). If
     the target is not met with in-scope changes, stop, document the cause and
     ask the owner (spec D5).
   - **Checkout CLS 0.30:** first read the shifting elements Lighthouse
     names in the baseline (`layout-shifts`) and fix *that* cause. The working
     hypothesis — the cart is read from `localStorage` after mount, so the page
     renders empty then fills — would be fixed with a reserved skeleton until
     the cart is read.
   - **Meta description (P3):** first verify with real crawler user agents
     (`curl` as Bingbot, facebookexternalhit, Googlebot, Lighthouse 13): Next 16
     already blocks metadata for its HTML-limited bot list, which includes
     Bingbot and "Chrome-Lighthouse". If only Lighthouse 13's newer UA is
     missed, extend `htmlLimitedBots` with it (the default list plus that
     token) rather than `/.*/`, which would slow every dynamic page's TTFB.
3. **Re-measure** with the same script; `results.md` table before/after per
   page.

| AC1 | One grey rule on dark/light-grey surfaces | `npm run a11y`: no `color-contrast` on the listed pages; `darkContrast.guard` |
| AC2 | 24 px hit areas | `npm run a11y` mobile: no `target-size` on home, `/tires/used` |
| AC3 | Visible text in the name | `npm run a11y`: no `label-content-name-mismatch`; component test |
| AC4 | `useId` clip, section `<h2>` | `npm run a11y`: no `duplicate-id`/`heading-order`; tests |
| AC5 | Approved logos + `brandLogos` set | Test: folder ↔ list; no logo 404 in a listing (network check) |
| AC6 | All of the above | `npm run a11y` scores 100 (or allow-listed with reason) |
| AC7 | The script fails on regressions | Run it once against a deliberately broken page (temporary), then the real site |
| AC8 | Before/after screenshots | 390 and 1280 px of each touched page in `results.md` |
| AC9 | `perf:lab` baseline before Part B | `baseline.json` committed with date and commit |
| AC10 | Home TBT fixes from the baseline | `perf:lab`: home mobile median TBT < 200 ms |
| AC11 | Checkout skeleton | `perf:lab`: `/checkout` CLS < 0.1 mobile and desktop |
| AC12 | Verified UA behaviour; `htmlLimitedBots` if needed | `curl` per UA shows the meta in `<head>`; Lighthouse SEO 100 on the tire page |
| AC13 | Priority fixes and deferrals | `perf:lab`: mobile LCP medians below the baseline, each change named |

## Tradeoffs / alternatives

- **Fix only failing elements** (rejected in D2): fewer visible changes, but the
  same grey on unmeasured pages would still fail.
- **CI job** (rejected in D6): no CI exists for this yet; a local script in the
  DoD is enough and costs nothing to run.
- **`htmlLimitedBots: /.*/`**: guaranteed `<head>` metadata, but every
  dynamic page's TTFB waits on its metadata — measured before choosing.
- **Lighthouse via `npx`** vs devDependency: `npx` downloads on each run and
  is slower; a pinned devDependency is reproducible (~30 MB, dev only).

## Risks

- **Visual drift** from lighter greys: checked with before/after screenshots;
  the brand colours do not change.
- **Logo rights:** official logos are used to identify the brand of a product
  actually sold (nominative use), as the 161 existing ones already are; the
  owner approves each.
- **Lab noise:** 5 runs and medians; a CPU-throttled laptop varies — the
  baseline and the re-measure run on the same machine, back to back.
- **Home deferral changes behaviour** (e.g. the 3D preview loading later):
  limited to below-the-fold or on-interaction content; tested by hand.
- **Size of the feature:** two halves; Part A can merge alone if Part B needs
  more time (the tasks keep them separable).

## Out of scope

- Hero video and 3D viewer redesigns; field data (CrUX) dashboards; layout
  redesigns.
